部署指南

Stellar 是一个静态链接的单二进制服务：Web 控制台、数据库迁移和内置数据库都在二进制里。本文覆盖物理机（二进制 / systemd / deb / npm）与 Kubernetes（Helm / 原生 YAML）两种场景，以及全部参数、目录结构和排错方法。

本文所有命令都以 admin 或 root 在 Linux x86_64 上执行；把 1.0.0 替换成你要安装的版本号。

5 分钟快速开始#

手里已经有安装包，或者只想先把服务跑起来看一眼？物理机三步就够。安装包在 Releases 页面，命令里的版本号请替换为 Releases 页展示的最新版本。

# 1. 下载并解压（目录名带版本号，升级时互不覆盖）
$ wget https://github.com/jlon/stellar/releases/download/v1.0.0/stellar-1.0.0-linux-amd64-musl.tar.gz
$ tar xzf stellar-1.0.0-linux-amd64-musl.tar.gz

# 2. 启动（数据目录不存在会自动创建）
$ cd stellar-1.0.0 && ./bin/stellar server ./data
# ↳ 控制台会打印一次性管理员密码，记下来

# 3. 打开浏览器，用 admin + 上面的密码登录
# http://<服务器IP>:9527

这是临时验证用的最小步骤。生产部署请继续看对应章节：

物理机 · 二进制 物理机 · systemd Debian 包 npm Docker Kubernetes · Helm Kubernetes · YAML

开始之前#

Stellar 只需一个二进制和一块可写磁盘，但下面这几条决定了你会不会在部署过程中卡住。

系统要求#

项目要求
操作系统64 位 Linux（内核 3.10+，含 CentOS 7 等老发行版）
硬件2 核 / 2 GB 内存 / 10 GB 磁盘起步
网络能访问被管理集群的 FE：9030（MySQL 协议）与 8030（HTTP，用于取指标）
端口对外提供 9527；可改
数据库无需另装：内置 SQLite；也可指定外部 MySQL / PostgreSQL
运行时依赖无。二进制全静态链接，目标机不需要 glibc 匹配、不需要 Node、不需要 JDK

安装包选择#

每个版本发布四种安装包，装的是同一个二进制，按环境选即可：

静态二进制压缩包 .tar.gz

任意 Linux，解压即用。物理机裸布首选。
Debian 包 .deb

Debian / Ubuntu，自动建用户并注册 systemd 服务。
容器镜像 ghcr.io/jlon/stellar

已有 Docker / Kubernetes 环境。
npm 包 .tgz

已有 Node 环境的机器；服务本身不需要 Node。
安全要求高的环境先校验 Release 附带的 SHA256SUMS：sha256sum -c SHA256SUMS --ignore-missing。npm 与 DEB 包各自附带 .sha256 文件。

首次启动必读#

所有安装方式共用同一套首次启动逻辑：

1

自动创建管理员并在控制台打印一次性随机密码：

Created initial user 'admin' with password: dZ6b8V5wDTnCnVaQ

This is shown once. Change it after first login.
2

登录后立刻改密码（右上角用户菜单 → 用户设置）。

3

所有状态都在一个数据目录里，备份它就是备份全部：

<数据目录>/
├── stellar.db              # 平台库（SQLite；WAL 模式，同目录有 -wal/-shm 文件）
├── .jwt-secret             # 登录签名密钥，首次启动自动生成，权限 0600
└── logs/
    └── stellar.2026-09-17  # 按天轮转的运行日志
想跳过随机密码？启动前设置环境变量 STELLAR_ROOT_PASSWORD=你的密码。
密码只在数据目录为空时创建一次；已有数据的库不会被覆盖或重置。

物理机部署：二进制压缩包（裸布）#

最直接的方式：下载、解压、指定数据目录启动。

# 1. 下载并解压（新版本解压到 stellar-<版本号>/ 目录，互不覆盖）
$ wget https://github.com/jlon/stellar/releases/download/v1.0.0/stellar-1.0.0-linux-amd64-musl.tar.gz
$ tar xzf stellar-1.0.0-linux-amd64-musl.tar.gz
$ cd stellar-1.0.0

# 2. 准备数据目录（目录不存在时会自动创建，但父目录权限要对）
$ sudo mkdir -p /var/lib/stellar
$ sudo chown $(whoami) /var/lib/stellar

# 3. 启动，指定数据目录
$ ./bin/stellar server /var/lib/stellar
# 控制台会打印一次性管理员密码，记下来

# 4. 另开一个终端验证
$ curl http://127.0.0.1:9527/health
OK

压缩包内容

路径说明
bin/stellar服务主程序（内含 Web 控制台与数据库迁移）
bin/stellar.sh简易启停脚本：start / stop / status / restart / logs
conf/config.toml参考配置（用 --config 指定才会生效）
data/、logs/空目录占位，供 cwd 相对路径使用

启动方式对照

# 零配置：数据落在当前目录的 data/ 下（适合试用）
$ ./bin/stellar server

# 显式数据目录（生产推荐，避免"在哪个目录启动"影响数据位置）
$ ./bin/stellar server /var/lib/stellar

# 环境变量方式（等价）
$ STELLAR_DATA_DIR=/var/lib/stellar ./bin/stellar server

# 用配置文件（配置文件模式：数据路径由配置文件决定）
$ ./bin/stellar server --config /etc/stellar/config.toml

# 用命令行覆盖单项参数
$ ./bin/stellar server /var/lib/stellar --server-port 9090
裸布的生产要点：nohup 只适合临时验证。生产请用 systemd 托管（下一节），否则进程崩溃不会自动拉起、开机也不会自启。

物理机部署：systemd 托管#

推荐的生产做法：专用系统用户 + 固定数据目录 + 崩溃自动重启。

# 1. 安装二进制到 /usr/local/bin
$ sudo install -m755 stellar/bin/stellar /usr/local/bin/stellar

# 2. 建专用用户与数据目录
$ sudo useradd --system --home /var/lib/stellar --shell /usr/sbin/nologin stellar
$ sudo mkdir -p /var/lib/stellar
$ sudo chown -R stellar:stellar /var/lib/stellar

# 3. 安装 systemd 单元（默认走数据目录模式，无需配置文件）
$ sudo cp deploy/systemd/stellar.service /etc/systemd/system/
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now stellar

# 4. 取一次性密码
$ sudo journalctl -u stellar | grep 'password:'

随包提供的 unit 文件

[Unit]
Description=Stellar - OLAP Cluster Management Platform
After=network.target

[Service]
Type=simple
User=stellar
Group=stellar
WorkingDirectory=/var/lib/stellar
ExecStart=/usr/local/bin/stellar server /var/lib/stellar
Restart=on-failure
RestartSec=3
LimitNOFILE=65536
# 可选：固定首次管理员密码（不设则日志中打印一次性随机密码）
# Environment=STELLAR_ROOT_PASSWORD=change-me
# Environment=APP_SERVER_PORT=9527

[Install]
WantedBy=multi-user.target
默认 unit 使用数据目录模式：数据库、.jwt-secret 与日志都在 /var/lib/stellar/ 下。需要外部数据库或其他高级配置时，再显式改为 --config；配置模式必须提供 auth.jwt_secret 或 APP_JWT_SECRET。

物理机部署：Debian / Ubuntu（.deb）#

一条命令完成安装、建用户、注册并启用 systemd 服务。

$ wget https://github.com/jlon/stellar/releases/download/v1.0.0/stellar-server-1.0.0-amd64.deb
$ sudo apt install ./stellar-server-1.0.0-amd64.deb
$ sudo systemctl start stellar

# 查看一次性管理员密码
$ sudo journalctl -u stellar | grep 'password:'

安装后的文件布局

路径说明
/opt/stellar/bin/stellar主程序
/opt/stellar/conf/config.toml配置（注册为 conffile，升级不会被覆盖）
/opt/stellar/data/、/opt/stellar/logs/数据与日志（属主 stellar:stellar，权限 750）
/usr/bin/stellar软链，任意目录可直接敲 stellar
/lib/systemd/system/stellar.servicesystemd 单元（WorkingDirectory=/opt/stellar）

升级：下载新版 .deb 后再次 sudo apt install ./stellar-server-<新版本>-amd64.deb，数据和配置都会保留。

物理机部署：npm 分发#

适合机器上已有 Node 环境的情况。npm 只是分发通道，服务端本身不依赖 Node。

$ wget https://github.com/jlon/stellar/releases/download/v1.0.0/stellar-server-1.0.0.tgz
$ sudo npm install -g ./stellar-server-1.0.0.tgz
$ stellar --version

# 启动（数据目录模式）
$ stellar server /var/lib/stellar
npm 全局安装只释放文件与命令软链，不会注册也不会自动启动系统服务。生产环境请配合 systemd 使用：unit 的 ExecStart 指向 /usr/local/bin/stellar server /var/lib/stellar（npm 默认 prefix 为 /usr/local，可用 npm config get prefix 确认）。

物理机部署：防火墙与 SELinux#

物理机上最常见的两个"服务起来了但访问不了"的原因，先在这里解决掉。

放行端口#

# firewalld（CentOS / RHEL / 麒麟）
$ sudo firewall-cmd --permanent --add-port=9527/tcp
$ sudo firewall-cmd --reload

# ufw（Debian / Ubuntu）
$ sudo ufw allow 9527/tcp

# 云主机还要在控制台的安全组里放行同一个端口
如果 Stellar 只给内网或本机用，也可以只监听回环：--server-host 127.0.0.1，再交给 Nginx 反代。

SELinux（CentOS / RHEL 系）#

症状：chown 之后服务仍然报 Permission denied，写不了数据库或日志。

# 1. 确认是不是 SELinux 拦的
$ sudo ausearch -m AVC -ts recent | tail -5

# 2. 看数据目录当前的标签
$ ls -Zd /var/lib/stellar

# 3. 让目录回到标准标签（默认应该就是 var_lib_t）
$ sudo restorecon -Rv /var/lib/stellar

# 4. 若数据目录放在了非标准路径（如 /data、/opt），给它打标签
$ sudo semanage fcontext -a -t var_lib_t "/data/stellar(/.*)?"
$ sudo restorecon -Rv /data/stellar
不要把 setenforce 0 当常规手段（重启即失效，且降低整机安全性）。上面的标签方式可以长期生效。

物理机部署：完全离线环境#

Stellar 运行时没有任何外呼，离线安装只需把文件搬进去。

# 在有网的机器上下载（连同校验文件）
$ wget https://github.com/jlon/stellar/releases/download/v1.0.0/stellar-1.0.0-linux-amd64-musl.tar.gz
$ wget https://github.com/jlon/stellar/releases/download/v1.0.0/SHA256SUMS

# 拷进内网机器，先校验
$ sha256sum -c SHA256SUMS --ignore-missing

# 解压启动，流程同上
$ tar xzf stellar-1.0.0-linux-amd64-musl.tar.gz && cd stellar-1.0.0
$ ./bin/stellar server /var/lib/stellar
AI 助手是可选能力：不配置模型端点就不会发起任何外部请求，其余功能完全离线可用。

Docker 部署#

镜像里装的是同一个静态二进制，运行时以非 root 用户执行。数据、密钥、日志都在容器内 /data。

# 1. 启动（宿主目录 ./data 持久化全部状态）
#    想跟随最新版可把镜像 tag 换成 latest
$ docker run -d --name stellar \
    -p 9527:9527 \
    -v $(pwd)/data:/data \
    --restart unless-stopped \
    ghcr.io/jlon/stellar:1.0.0

# 2. 取一次性管理员密码
$ docker logs stellar 2>&1 | grep 'password:'

# 3. 验证
$ curl -f http://127.0.0.1:9527/health

docker compose#

services:
  stellar:
    image: ghcr.io/jlon/stellar:1.0.0   # 或 :latest
    container_name: stellar
    ports:
      - "9527:9527"
    volumes:
      - ./data:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9527/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

常用参数与变量#

项说明
数据目录容器内固定 /data，用卷挂出来即可；必须持久化，否则容器重建即丢数据与密钥
APP_SERVER_PORT容器内监听端口，默认 9527；改端口时记得同步映射
APP_JWT_SECRET固定登录密钥；不设则自动生成 /data/.jwt-secret 随卷持久
STELLAR_ROOT_PASSWORD指定初始管理员密码，省去查日志
APP_DATABASE_URL指向外部 MySQL / PostgreSQL（容器内无需装库）

升级与清理#

$ docker pull ghcr.io/jlon/stellar:1.0.0
$ docker rm -f stellar
$ docker run -d --name stellar -p 9527:9527 -v $(pwd)/data:/data ghcr.io/jlon/stellar:1.0.0
# 数据卷不动，升级就是重建容器

# 确认不再需要后再删数据
$ rm -rf ./data
镜像发布在 GitHub Container Registry，稳定版本会打 1.0.0 / 1.0 / 1 / latest 四个标签。
私有化环境可先 docker save 导出 tar，拷进内网后 docker load。

Kubernetes 部署：Helm（推荐）#

Chart 位于仓库 deploy/chart/，已预置探针、资源限额、Ingress 与持久化。

# 从源码目录安装
$ git clone https://github.com/jlon/stellar.git && cd stellar
$ helm install stellar deploy/chart --namespace stellar --create-namespace

# 或使用发布出来的 chart 包
$ helm install stellar https://github.com/jlon/stellar/releases/download/v1.0.0/stellar-1.0.0.tgz \
    --namespace stellar --create-namespace

# 取一次性管理员密码
$ kubectl logs -n stellar deploy/stellar | grep 'password:'

常用 values

键默认说明
replicaCount1固定为 1：内置 SQLite 只支持单写者。需要多副本请改用外部 MySQL / PostgreSQL
image.repository / tagghcr.io/jlon/stellar / Chart.AppVersion镜像地址与版本
service.port9527Service 端口
ingress.enabled / ingress.hostsfalse / —外部访问入口
persistence.enabled / sizetrue / 10GiPVC 大小；existingClaim 可复用已有 PVC
resources{}requests/limits
readinessProbe / livenessProbe已配置默认探测 /health
jwtSecret""留空时由 Chart 随机生成 32 位密钥写入 Secret。注意：每次 helm upgrade 都会重新随机 → 所有登录态失效，生产建议显式设置
configuration内置默认渲染成 ConfigMap 挂到 /app/conf/config.toml
# 生产常用：指定镜像、加大存储、开 Ingress，并把 secrets 放 values 文件
$ cat > stellar-values.yaml <<'EOF'
image:
  tag: "1.0.0"
persistence:
  size: 50Gi
ingress:
  enabled: true
  hosts:
    - host: stellar.example.com
      paths:
        - path: /
          pathType: Prefix
resources:
  requests: { cpu: "500m", memory: "512Mi" }
  limits:   { cpu: "2",    memory: "2Gi" }
EOF
$ helm install stellar deploy/chart -n stellar --create-namespace -f stellar-values.yaml

# 升级与回滚
$ helm upgrade stellar deploy/chart -n stellar -f stellar-values.yaml
$ helm rollback stellar 1 -n stellar
$ helm uninstall stellar -n stellar        # PVC 默认保留

不想引入 Helm 时，用仓库里的单文件清单，包含 6 类资源：

资源名称作用

Kubernetes：持久化、探针与数据路径#

  • 数据卷：容器内一切状态都在 /data（stellar.db、.jwt-secret、logs/）。清单与 Chart 都把它挂到 PVC，不要用 emptyDir，否则 Pod 重建即丢数据。
  • 副本数：内置 SQLite 只允许单写者，因此 replicas 固定为 1。需要高可用时把 database.url 指向外部 MySQL/PostgreSQL，再自行放开副本数。
  • 探针：/health 用于存活与就绪；数据库迁移发生在启动阶段，首次启动给足 initialDelaySeconds（清单默认 30s）。
  • 配置来源：ConfigMap 提供 config.toml 时走配置文件模式；不提供则完全零配置启动，数据落在数据目录默认位置。
  • 日志：写在 /data/logs 的同时输出到 stdout，所以 kubectl logs 与 PVC 里都能看到；kubectl logs 取一次性密码最方便。
  • PVC 扩容：kubectl -n stellar patch pvc stellar-data -p '{"spec":{"resources":{"requests":{"storage":"50Gi"}}}}'（需 StorageClass 支持在线扩容）。

命令行参数#

命令形式为 stellar server [数据目录] [参数]。不写 server 时等价于 stellar server。

参数作用示例
[数据目录]位置参数。库、密钥、日志都放这里；默认 $STELLAR_DATA_DIR 或 ./dataserver /var/lib/stellar
--config <PATH>指定配置文件，走配置文件模式（数据路径由文件决定）--config /etc/stellar/config.toml
--server-host <HOST>监听地址，默认 0.0.0.0--server-host 127.0.0.1
--server-port <PORT>监听端口，默认 9527--server-port 9090
--database-url <URL>数据库连接串（sqlite / mysql / postgres）--database-url mysql://u:p@db:3306/stellar
--jwt-secret <SECRET>登录签名密钥；不设则自动生成并持久化--jwt-secret "$(openssl rand -hex 32)"
--jwt-expires-in <DURATION>登录有效期，默认 24h--jwt-expires-in 8h
--log-level <LEVEL>日志级别--log-level info,stellar_backend=debug
--metrics-interval-secs <DURATION>指标采集间隔，默认 30s--metrics-interval-secs 1m
--metrics-retention-days <DAYS>指标保留天数，默认 7d--metrics-retention-days 30d
--metrics-enabled <BOOL>是否启用采集--metrics-enabled false
--audit-database <DB>StarRocks 审计库名，默认 starrocks_audit_db__--audit-database audit_db
--audit-table <TABLE>审计表名，默认 starrocks_audit_tbl__--audit-table audit_tbl
--help / --version查看帮助与版本stellar server --help

适合容器与 systemd（Environment=）场景。优先级：命令行 > 环境变量 > 配置文件 > 默认值。

配置文件字段#

只在显式传入 --config 时读取。完整示例（含默认值）：

[server]
host = "0.0.0.0"                          # 监听地址
port = 9527                               # 监听端口

[database]
url = "sqlite://data/stellar.db"          # 内置 SQLite（相对 WorkingDirectory）
# url = "sqlite:///var/lib/stellar/stellar.db"
# url = "mysql://user:pass@127.0.0.1:3306/stellar?charset=utf8mb4"
# url = "postgres://user:pass@127.0.0.1:5432/stellar"

[auth]
jwt_secret = ""                           # --config 模式必须填写，或设置 APP_JWT_SECRET
jwt_expires_in = "24h"                    # 登录有效期

[security]
permission_request_encryption_key = ""    # 加密权限申请里的数据库密码；留空则该功能拒绝执行（见下文）

[logging]
level = "info,stellar_backend=debug"      # 日志级别
file = "logs/stellar.log"                 # 日志文件；删除此行则只输出到控制台

[static_config]
enabled = true                            # 是否提供 Web 控制台（内嵌资源）
web_root = "web"

[metrics]
interval_secs = "30s"                     # 指标采集间隔
retention_days = "7d"                     # 指标保留时长
enabled = true                            # 采集开关

[audit]
database = "starrocks_audit_db__"         # StarRocks 审计库
table = "starrocks_audit_tbl__"           # StarRocks 审计表

[agent]
enabled = true                            # AI 运维事件循环；离线环境可关
interval_secs = "30s"                     # 循环周期
event_retention_days = 14                 # 事件保留天数
启动时会校验：端口不能为 0、数据库连接串不能为空、metrics.interval_secs 与 retention_days 必须大于 0。配置错误会直接拒绝启动并在日志里说明原因。

部署之后：让平台真正可用#

服务跑起来只是第一步。下面四步决定这个平台能不能日常用起来。

1. 登录并改掉初始密码#

浏览器打开 http://<服务器IP>:9527，用 admin 与一次性密码登录，随后在右上角用户菜单 → 用户设置里修改密码。

2. 添加被管理集群#

进入「集群管理 → 添加集群」，填写：

字段说明
部署模式存算一体（shared-nothing）或存算分离（shared-data），选错会导致节点页与容量信息不匹配
集群类型StarRocks 或 Apache Doris
FE 地址FE 节点的 IP 或域名
HTTP 端口 / 查询端口默认 8030 / 9030；改了端口要按实际填
账号用于管理操作的账号；建议先用监控账号连通测试，再按需授权
Stellar 需要同时访问 FE 的 9030（MySQL 协议）与 8030（HTTP）；后者用于拉取指标，不通会导致监控图全为 0。

3. 用只读监控账号，不要用 root#

在 StarRocks / Doris 侧创建一个专用只读账号，再把它填到集群配置里。脚本与所需权限见 监控账号配置说明。

4. 可选但建议#

  • 开启审计：在 StarRocks 侧配置审计插件后，「审计日志」页面才有数据（库表名对应 [audit] 配置）。
  • 外部数据库：单机 SQLite 足够；需要高可用或多人并发写入时切到 MySQL / PostgreSQL，参见 外部数据库说明。
  • 日志轮转：内置日志不自动删除，按前文配置 logrotate。
  • 组织与角色：多团队使用时先建组织，再按组织分配集群与用户，避免所有人挤在默认组织里。

数据、备份、升级#

备份与恢复#

# 备份：整个数据目录（停服后最稳）
$ sudo systemctl stop stellar
$ sudo tar czf stellar-backup-$(date +%F).tgz -C /var/lib stellar
$ sudo systemctl start stellar

# Kubernetes
$ kubectl -n stellar exec deploy/stellar -- tar czf - -C /data . > stellar-backup.tgz

# 恢复：解回原路径后启动即可

升级#

原则：替换程序，不动数据目录。启动时数据库结构变更会自动执行。

方式操作
压缩包停服 → 用新版 bin/stellar 覆盖 → 启服
debsudo apt install ./stellar-server-<新版本>-amd64.deb
npmsudo npm install -g ./stellar-server-<新版本>.tgz
Dockerdocker pull 新镜像 → 用同一个数据卷重建容器
Helmhelm upgrade stellar deploy/chart -n stellar --set image.tag=<新版本>

日志#

  • 按天轮转，文件名形如 stellar.2026-09-17；不会自动删除，请用 logrotate 或定时任务清理。
  • 日志目录不可写时不会崩溃：自动降级为只输出到 stdout 并打印一行告警。
  • 控制台（右上角）可在「系统管理 → 操作日志」一键打包当前全部日志为 zip，含审计留痕。
  • logrotate 示例（必须用 copytruncate，因为进程持有文件句柄）：
/var/lib/stellar/logs/stellar.* {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}

健康检查#

$ curl -f http://127.0.0.1:9527/health   # 就绪返回 OK
$ curl -f http://127.0.0.1:9527/ready    # 就绪探针

排障#

启动失败怎么查#

$ sudo systemctl status stellar -l        # 状态与最近输出
$ sudo journalctl -u stellar -n 80 --no-pager
$ kubectl -n stellar logs deploy/stellar --tail=80
现象原因与处理
Address already in use端口被占用。换端口：--server-port 9090 或改配置里的 server.port
Permission denied（写日志/库）数据目录属主不对。执行 chown -R stellar:stellar /var/lib/stellar
页面 404 但 /health 正常前端资源未启用或未构建进二进制：确认配置里 static_config.enabled = true，并使用官方发布的二进制
数据库连不上检查 database.url 协议、账号权限与网络连通；外部库需提前建库
指标图都是 0FE 的 8030 端口不通，或监控账号无权限。/metrics 只导出 FE 指标，BE 容量取自 SHOW BACKENDS
忘记管理员密码若数据目录为空时丢过密码：停服后删除 stellar.db* 会清空平台数据并重新生成密码；有数据时请从备份恢复
磁盘写满内置 SQLite 与日志同在一处。清理 logs/ 旧文件，或把 database.url 迁到外部库

关于审计数据#

「审计日志」页面读取的是 StarRocks 侧已开启的审计表（默认库 starrocks_audit_db__、表 starrocks_audit_tbl__）。需要在 StarRocks 集群上先配置审计插件，并把库表名对应到 Stellar 的 [audit] 配置；未配置时该页面为空，不影响其他功能。

卸载#

# deb
$ sudo systemctl disable --now stellar
$ sudo apt remove stellar-server        # 保留 /opt/stellar 数据
$ sudo apt purge stellar-server         # 连配置一起删除
$ sudo rm -rf /opt/stellar              # 确认不再需要数据后再删

# 压缩包 / npm
$ sudo systemctl disable --now stellar
$ sudo rm -f /etc/systemd/system/stellar.service && sudo systemctl daemon-reload
$ sudo rm -f /usr/local/bin/stellar
$ sudo rm -rf /var/lib/stellar          # 数据目录，谨慎

# Kubernetes
$ helm uninstall stellar -n stellar     # PVC 会保留
$ kubectl -n stellar delete pvc stellar-data   # 确认后再删数据
