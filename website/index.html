From a bare FE address to a diagnosed bottleneck

Stellar reads the cluster the way an operator does: system tables, metrics endpoints and the audit log. Nothing to install on the cluster side.

01Connect

Add a StarRocks or Doris FE address with a read-only monitoring account. Stellar detects the deployment mode and inventories FE, BE and compute nodes.

02Observe

Throughput, latency percentiles, errors, disk and compaction are collected on an interval and kept for trend and capacity analysis.

03Diagnose and act

Query profiles are parsed into an execution graph. Rules name the bottleneck; the AI assistant explains the root cause and proposes a change you approve.

Built for teams that answer to an auditor

Multi-organization isolation, role-based permissions, and an approval workflow for database accounts — with every change written to an operation log.

Stellar · Permissions

TENANCY

Organization isolation

Each organization sees only its own clusters and users. Cross-organization visibility is limited to super administrators.

Who created, changed or deleted what, and when — query history and operation history are kept separately.

Deploy it the way your environment expects

The same statically linked binary ships in every format. State lives in one directory, so an upgrade is a binary swap.

Step-by-step deployment guide →

Static binary

tar.gz

musl build, no runtime dependencies. Extract, run, done.

./stellar server /var/lib/stellar

Debian package

.deb

Creates the service user, installs the systemd unit and enables the service.

apt install ./stellar-server.deb

Container

Docker

Published to GitHub Container Registry. Persist a single volume and you are done.

docker run -v $PWD/data:/data ghcr.io/jlon/stellar

Helm chart

Kubernetes

Probes, resources, ingress and persistence pre-wired for a production install.

helm install stellar deploy/chart

Kubernetes manifests

YAML

Namespace, config map, secret, workload and ingress in a single file to adapt.

kubectl apply -f deploy/k8s/deploy-all.yaml

npm package

.tgz

A distribution channel for machines with Node present. The server itself needs no Node runtime.

npm i -g ./stellar-server.tgz

Questions we get before the first install

What has to be installed besides Stellar?

Nothing. The released binary is statically linked and embeds the web console, the schema migrations and an SQLite database. MySQL and PostgreSQL are supported as external stores by changing one URL.

Can it run in a fully offline network?

Yes. There is no phone-home and no external service required at runtime. The AI assistant is optional and only active if you configure a model endpoint.

Does it need agents on the cluster nodes?

No. Stellar talks to the FE over the MySQL protocol and the HTTP metrics endpoint, and reads the audit table when available. Create a dedicated read-only monitoring account rather than using root.

How do upgrades work?

Replace the binary and restart. Database, uploads and logs live in one data directory; schema migrations run automatically at start-up.

What is the license?

Apache-2.0. Run it internally, modify it, redistribute it — including commercially.
