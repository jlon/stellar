# 权限管理

## Direction contract

**THESIS**：权限管理是一次明确、可复核的授权工作流，而不是把所有字段平铺的后台表单；页面拒绝统计卡片和嵌套面板堆砌。

**OWN-WORLD**：沿用 Nebular 暗色主题与主题变量。中性表面承载信息，主色仅表示当前选择和提交操作；使用紧凑的文字 Tab、32px 表单控件、1px 分隔线和统一的 4–8px 圆角。

**STORY**：申请人依次确认申请对象、资源范围和业务原因，并在提交前看到完整摘要；审批人先扫描待办，再进入详情作出带理由的决定；所有人可查看当前权限与申请状态。

**FIRST VIEWPORT**：直接进入文字 Tab，不重复页面或卡片标题。申请页占满布局提供的工作区：左侧依次填写“申请对象 → 资源范围 → 申请说明”，右侧为紧凑的粘性确认栏与提交动作；窄屏时确认栏移至表单末尾。

**FORM**：渐进披露单页表单。三种申请类型用紧凑的原生 button group 选择；资源层级只在需要时出现；权限使用带文字说明的 checkbox 网格；右栏实时确认操作、对象、范围和权限；提交操作位于申请说明之后，使用文字明确的 primary outline 按钮，重置保持图标化。

**FINISH**：unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Security & authorization boundaries

页面只负责解释规则，后端在提交、预览、审批、执行四个阶段重复校验：

- **受保护主体**：`root` 等受保护数据库账户，以及 `root`、`admin`、`operator`、`public` 等内置/特权角色不出现在可选列表，也无法通过申请变更；前端过滤只是体验，后端集中拒绝。
- **集群来源**：申请、账户/角色查询、预览与执行都绑定当前组织在服务端解析出的活跃集群；客户端传入的 `cluster_id` 只是提示值，不匹配即拒绝。
- **权限与标识符**：权限码按资源层级白名单校验，标识符限 `[A-Za-z_][A-Za-z0-9_]*`（资源路径另允许 `*` 通配），账户 host 固定由平台管理，`WITH GRANT OPTION` 不开放。
- **密码是 write-only**：新建数据库用户的初始密码只在提交时接收，加密存储于独立列，且不会出现在申请理由、列表/详情响应、SQL 预览或执行审计中；审批执行时在内存中解密，执行失败信息也不回带 SQL 文本。
- **审批与并发**：申请人只能查看/取消自己的申请，审批人需具备审批角色且不能自审；状态流转使用条件更新（`WHERE status = 'pending'`）保证并发下只有一次生效；历史工单在执行前重新校验组织、集群与最新规则。
