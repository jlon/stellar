# 物化视图创建与状态

遵循 [Stellar 设计系统](../MASTER.md)。创建沿用集群表单的 `side-sheet`：一个右侧全高、44rem 的抽屉（用于阅读复杂 SQL），滚动主体、固定操作栏。新增能力不是增加模态层，而是把复杂 DDL 的定义与审阅放在同一工作流。

## 创建流程

1. **配置**：选择目标库、名称；选择单表投影（Schema Explorer 逐级选普通表及列），或输入单条 `SELECT` 定义关联、聚合、过滤等查询。设置可选结果分区列、数据分布（默认／随机／HASH，分桶数）、副本数、StarRocks 排序结果列，以及立即或延迟构建、手动或定时刷新。
2. **校验并预览**：服务端校验只读单条 SELECT，针对当前集群引擎生成 DDL，并用 `EXPLAIN SELECT` 检查查询语义；失败时保留输入并显示原因，不执行创建。
3. **人工确认**：原抽屉的审阅区展示完整 DDL，返回修改则清除预览。确认后提交预览版本，服务端检查活跃集群标识、再次生成并比对 DDL 后执行、记审计、刷新列表；延迟构建的 MV 需后续手动发起首次刷新。

交互约束：静态说明用低对比度提示，失败才使用 `nb-alert`；表单控件统一 Nebular small；审阅代码区可独立滚动；提交中不可重复操作。不要把 SELECT/DLL 当作普通查询经通用执行接口发送，也不要以客户端生成的预览代替服务端校验。

## 优化机会与智能运维

- 机会识别服务端按活跃集群与审计窗口缓存 5 分钟；切换窗口不会混用结果，工具栏“刷新”强制重新读取审计日志。缓存仅保存已脱敏的聚合响应。
- 每条候选的“智能分析”复用全局助手抽屉，传递来源表、频率、延迟和脱敏 SQL 模式。候选是性能证据，不能当作可执行指令。
- 助手若判断值得创建，只能发起 `create_materialized_view` 受控动作。模型提交结构化自定义 SELECT 草案，服务端绑定会话集群、执行预览并保存生成的 DDL；完整助手的确认卡展示该 DDL。确认时再次预览并精确比对后才执行，申请、确认人与结果都保留在动作审计中。

## 引擎边界

- 仅异步 MV；同步 ROLLUP 与异步 MV 有不同语义，不在此创建入口混用。
- StarRocks 使用 `REFRESH IMMEDIATE|DEFERRED`、可选 `PARTITION BY`、`DISTRIBUTED BY`；Doris 使用 `BUILD IMMEDIATE|DEFERRED REFRESH AUTO`，分区写作 `PARTITION BY (列)`。查询语法和分区映射的最终合法性由目标引擎确认。
- 自定义 SELECT 只接受服务端 SQL parser 能验证的查询；不接受多语句、写入型 CTE、`SELECT INTO`、锁表读取。受引擎支持但 parser 不识别的方言表达式会明确提示，不能以跳过校验作为降级。解析后重新生成的 SELECT 会移除注释和查询提示；审阅区展示的才是实际执行版本。控制面为避免误用而限制 SQL 20KB、结果列最多 128、HASH/排序列最多 8、分桶数 1–1024、副本数 1–10；这些是产品防护边界，不代表引擎自身上限。

## 验收

桌面窗口在错误和溢出时固定操作栏始终可见；从登录、配置、预览、确认、列表与 DDL 核对、首次刷新到删除测试对象跑真实浏览器全链路；测试对象清理后服务端返回 404。
